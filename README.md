# OpenCode v2 Meta-Optimizer

مجموعة إعدادات وأدوات مساعدة لمراجعة وتحسين بيئة **OpenCode v2** لمستخدم فردي. المشروع قالب قابل للتخصيص، وليس أداة رسمية من OpenCode ولا يدّعي اكتشاف كل إعدادات الجهاز تلقائياً.

> **تنبيه مهم:** ملفات المشروع لا تُثبت OpenCode ولا تغيّر إعدادات جهازك تلقائياً. ابدأ بنسخ احتياطية، وافحص القالب قبل دمجه مع إعداداتك الحالية. الإعدادات تختلف باختلاف نظام التشغيل وإصدار OpenCode ومزود النموذج.

## ما الذي يتضمنه؟

- `config/opencode.jsonc`: إعداد أساس آمن نسبياً يفضّل طلب الموافقة على أوامر shell والتعديلات.
- `.opencode/agents/`: وكلاء تدقيق ومراجعة بصيغة Markdown، مع منع shell والتعديلات في إعدادات الوكيل.
- `.opencode/skills/`: مهارة تدقيق الإعدادات ومهارة مراجعة الشيفرة.
- `scripts/audit_config.py`: فاحص محلي مستقل لصياغة الإعدادات وملاحظات ثابتة محدودة.
- `scripts/recommend_features.py`: يقرأ صفحات الوثائق الرسمية وسجل التغييرات، ويتعرف على إصدار CLI والإعدادات المحلية الظاهرة، ثم يولّد تقرير توصيات Markdown دون تعديل الإعدادات.
- `scripts/deep_audit.py`: مدقق أعمق يكتشف طبقات الإعداد، أسماء الحقول الحديثة والقديمة، الحقول الموسومة deprecated في المخطط الحي، الوكلاء وصلاحياتهم، مسارات Skills الرسمية والتوافقية، MCP وPlugins وCustom Tools وCommands وFormatter/LSP، مع تنبيهات على ملفات instruction إضافية ومؤشرات الأدوات المحلية. يخرج تقرير Markdown بالأدلة والمخاطر، ولا يطبّق التوصيات.
- `run-report-windows.bat`: مشغّل Windows بالنقر المزدوج؛ لا يحتاج إلى أوامر PowerShell، ويتطلب Python 3.10 أو أحدث. فحص MCP الحي اختياري ويطلب الإذن قبل الاتصال.
- `docs/`: شرح الحدود، الحقائق الرسمية التي بني عليها التدقيق، وخطة التحقق.

لا يتضمن القالب أسماء نماذج أو MCP غير مؤكدة. أضف مزودك وخوادم MCP بعد التحقق من الدعم، التكلفة، وسياسة البيانات. لا تضع مفاتيح API في المستودع.

## التحقق المحلي

المتطلبات: Python 3.10+ (لا توجد dependencies خارجية).

```bash
python3 scripts/audit_config.py config/opencode.jsonc
python3 scripts/recommend_features.py --project-dir "/path/to/your/project" --output opencode-feature-report.md
python3 scripts/deep_audit.py --global-only --output opencode-deep-audit.md
python3 -m unittest discover -s tests -v
```

الفاحص البسيط يتحقق من صياغة JSON/JSONC فقط. المدقق العميق يستدعي `opencode debug config` من نسخة CLI المثبتة ويستخدم الإعداد المحسوم لهذه النسخة أولاً. ويقارن ملفات المصدر بالمخطط الرسمي الحي كمرجع مساعد، لا كحَكَم وحيد؛ فإذا احتفظت النسخة المثبتة بمفتاح، لا يصنّفه تحذير المخطط وحده كخطأ أو deprecated أو خطأ نوع. لأن صفحات الوثائق والمخطط قد يعرضان أمثلة من أجيال مختلفة، لا يجري ترحيل تلقائي؛ راجع سجل OpenCode المثبت واختبر التغيير على نسخة من الإعداد.

يفحص ملفات الإعداد دون تعديلها، ويستدعي `debug config` للقراءة المحسومة من CLI فقط؛ ولا يشغّل الوكلاء. الأمر قد يجلب إعدادات remote التي يدعمها الإصدار. **لا** يتحقق من صلاحية اعتماد نموذج أو من اتصال كل خدمة، ولا يقرأ قاعدة بيانات Desktop الخاصة أو مخزن المصادقة. يمكن تشغيله دون اتصال باستخدام `--offline`، وعندها لن يتوفر فحص المخطط والوثائق الحية. إذا لم يكن CLI في PATH، أدخل مسار ملف `opencode.exe` عند سؤال المشغّل أو استخدم `--cli`؛ ولتحليل الملفات فقط، استخدم `--skip-debug-config`. الخيار `--check-mcp` ينفذ `opencode mcp list` بموافقتك؛ وقد يبدأ عمليات محلية أو يتصل بخوادم بعيدة، ولذلك لا يعمل افتراضياً. لا يطبع التقرير محتوى الإعدادات أو resource patterns أو قيم الأسرار. لا تشارك التقرير قبل مراجعة المعرّفات التي قد تعتبرها خاصة.

## التشغيل على Windows دون أوامر PowerShell

نزّل ZIP من GitHub وفك ضغطه. إذا لم يكن Python مثبتاً، ثبّت Python 3.10 أو أحدث من [الموقع الرسمي](https://www.python.org/downloads/windows/) باستخدام واجهة التثبيت، مع تفعيل Python Launcher أو خيار إضافته إلى PATH. انقر نقراً مزدوجاً على `run-report-windows.bat`، والصق مسار مجلد المشروع عند الطلب؛ اتركه فارغاً لفحص إعدادات المستخدم العامة فقط. أدخل مسار `opencode.exe` إن لم يكن CLI في PATH. `debug config` يعمل تلقائياً لعرض الإعداد المحسوم من النسخة المحلية؛ ويمكنك تجاوز ذلك بخيار `--skip-debug-config`. عند السؤال عن MCP، اكتب `y` فقط إذا رغبت في اختبار الاتصال الحي؛ `N` أو Enter لا يشغّل فحص MCP. سيفتح التقرير الناتج تلقائياً في Notepad. هذا مشغّل للتقرير وليس مُثبّتاً للنظام، ولا يغيّر إعدادات OpenCode.

## الاستخدام مع OpenCode Desktop

OpenCode Desktop يستخدم بيئة OpenCode وإعداداتها وفق الإصدار المثبت؛ هذا المستودع لا يتصل بسطح مكتبك ولا يقرأ إعداداته عن بعد. راجع الوثائق الرسمية لإصدارك وحدد مسار الإعداد العالمي الصحيح لنظامك. المسار الشائع على Linux/macOS هو `~/.config/opencode/`، لكن Windows ومسارات الإعداد المخصصة قد تختلف.

1. خذ نسخة احتياطية من إعداداتك الحالية.
2. جرّب أولاً الوكلاء والمهارات داخل مجلد مشروع منفصل، بنسخ `.opencode/` إلى المشروع.
3. ادمج مفاتيح `config/opencode.jsonc` يدوياً مع إعداداتك؛ لا تستبدل ملفك العالمي كاملاً.
4. لا تنسخ القالب قبل مراجعة صلاحياته والنموذج ومزود الخدمة.
5. أعد تشغيل OpenCode Desktop عند الحاجة، ثم اختبر على مستودع تجريبي غير مهم.

## الأمان والخصوصية

- وكيل التدقيق ووكيل مراجعة الشيفرة محدودان بقراءة الملفات، مع منع `bash` والتعديل.
- قالب JSONC الحديث يطلب الموافقة على `bash` و`edit` و`webfetch` والوصول إلى ملفات خارج المشروع، ويمنع هذه الأفعال للوكلاء المقيّدين؛ قد تغيّر طبقات أعلى أولوية النتيجة.
- تشغيل MCP أو Plugin قد ينقل بيانات أو يشغّل شيفرة طرف ثالث. أضف أقل عدد ممكن، وافحص المصدر والصلاحيات وسياسة الخصوصية.
- لا تستخدم مهارات أو Plugins مجهولة على مشاريع حساسة. اختبرها في نسخة منفصلة.
- لا يُنصح بتفعيل أي تعديل تلقائي للنظام دون مراجعة بشرية ونسخة احتياطية.

## الحالة والخارطة

الحالة الحالية: **نسخة أولية محسّنة للتدقيق**. المدقق يكتشف الحقول الحديثة والقديمة، ويستفيد من المخطط والوثائق عند توفرهما. لا يثبت الإعدادات المخفية في Desktop أو سياسات المؤسسة، ولا ينفذ اختباراً للنماذج أو LSP أو Formatter. اختبار MCP اختياري ويتطلب اختيار المستخدم. يعرض توصيات ومخاطر ومصادر رسمية ولا يطبّق أي تغيير.
